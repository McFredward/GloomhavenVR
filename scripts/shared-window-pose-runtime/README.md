# Shared-window transport and initial-pose proof

`python3 scripts/check-shared-window-pose-runtime.py` compiles the production
source-frame codec, placement authority, roster collector, peer constructors,
samplers, receives, native-opening ledger, first-pose adoption, movement tracking
and movement elections. The scenario story, map story, quest, encounter and video
paths execute their original kernels. Record119 is serialized and parsed before
the receiver reconstructs the source's world pose.

Native window discovery, the session/roster inputs, transform storage and managed
quaternion arithmetic are explicit portable boundaries. Actual Unity rendering,
rectangles and grab-host writers are covered separately by
`check-shared-window-geometry-runtime.py`. Full golden vectors retain ownership
of the unchanged legacy19/21 byte grammar. These results establish neither a
headset picture nor complete native multiplayer progression.

Coverage includes different sender/viewer seats and zooms, host versus flat-host
surrogate authority, pending/missing/foreign metadata, late arrival, stale and
wrong story openings, manual movement outranking repeated host initialization,
the first visible snap not being republished as a new local drag, and decoder
source independence for shared movie placement. Mutations must compile and fail
their named assertion; a compiler error is never a passing negative control.

Quest/encounter first reveal also captures the exact local grab lifetime and
requires a snapshot received during that opening. A same-key reopen cannot reveal
an older cached pose while waiting for the next normal author snapshot. The proof
executes both refusal and subsequent fresh delivery for both coordinate frames;
a compiling mutation removing the receipt gate fails the reopened-float assertion.
This is a cached-pose lifetime fence, not a new native encounter identity protocol.
Story openings retain their existing opening ledger; causal quest browsing
selection has its separate production register and tests.

Every generated run retains source snapshots, hashes, build/runtime logs and
results. Completion invokes the canonical cache cleanup after reaping children.
