# Shared reward placement runtime boundary

The portable fixture executes the actual `RewardShowcasePlacement` class, host
spawn/finalization methods, compatible-session collector, reward initial-owner
election, generation-qualified reward handshake, shared grab-factor codec and
native Continue permission/dispatch kernels. Source pins retain the reward branch
in `ComputeHmdPose`, legacy arc reseat exclusion, pre-reveal easing rule and the
driver/census lifecycle that releases stale follower authority after disconnect.

Native windows, callback endpoints, transforms, camera, clipping/table constraints
and Unity arithmetic are explicit simulated boundaries. The test does not execute
the full conversion lifecycle, native reward coroutine, transport, headset or
Unity rendering. Reward identity changes, remote pose selection and peer aging are
boundaries; same-opening authority refresh executes the actual `ResolveReward`.
The callback case executes the post-quest native-dispatch branch with a simulated
endpoint. It proves the actual mod callback gate stays independent of placement
readiness, rather than claiming native gameplay completes.

Cases cover the native host, a cold follower with a stable compatible host census
but no avatar, an explicit absent-host decline promoting a reward surrogate, final
fit replaying the captured gaze, manual-pose retention, the already visible remote
window outranking a late lower-id host, wrong-key/expired poses, missing camera
and stale follower recovery after census reset, degraded transport or teardown.
Six compiling causal controls independently remove reward authority, reveal
waiting, chest identity, accepted-pose retention, stable roster collection and
degraded-transport authority recovery.

Each completed fixture invokes the canonical cache cleanup after its processes
are reaped. Original sources, hashes, runtime/build logs and result manifests
remain in `.planning/debug/shared-reward-placement-runtime/`.
