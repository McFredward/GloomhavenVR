# Level-up native runtime fixture

Run `python3 scripts/check-levelup-native-runtime.py` with a task-private
`ADB_SERVER_SOCKET` and `ADB_MDNS_AUTO_CONNECT=''`. Unity 2021.3.5, the read-only
game managed/assets reference and the existing UnityPy environment are required.
`--source-root` binds another checkout. `--output-dir` chooses the evidence root.
`--case NAME` is a partial run and never a complete suite pass.

The full production `LevelUpComposite`, `AnnouncementContinueView`, unchanged
tracker permission kernel, `ConfirmationOnOwner` and origin kernels execute in
Unity. The actual `FloatWantedFor` method and the exact `TryConvertWindow`
admission prefix execute too; the unrelated conversion body is a counted service
port after that prefix. Original game `ExtendedButton`, uGUI and TMP assemblies
run unchanged. Fixture-only Harmony patches provide translation, reject the
reward button's native click gate, and record unsafe controller activation.
These patches are never included in the mod.

Build737 adds the actual original TMP whitespace-only negative-size bounds witness
matching the Build736 +/-2^31 hardware spill. The production card-list envelope,
real final column pixels, owning GraphicRaycaster, original ExtendedButton pointer
dispatch and locked browse/reopen lifecycle execute. Native session, choice event,
permission and lock state remain explicit inputs; this does not bootstrap native
level-up actors or claim an actual card grant. The unchanged original
UIResetLevelUpWindow.ToggleDisplay path exposes this browser outside leveling with
locked cards. Its reset costs, campaign and character-control permissions stay native.

`export_inputs.py` reads the original `UICampaignRewardWindow.continueButton`
from `level9` (owner 16283, button 18225). It records complete native widget tree,
component object hashes, 307×65 frame, original nine-slice and SpriteSwap images,
glyph/character metrics, font atlas and actual font material 201. The inactive
controller hint is retained as a presentation input. The reference and cloned
button use those original images, font, material properties and game button
code. The canonical TMP source shader is independently checked against the
repository's pinned upstream hash; original Windows shader bytecode is not run.

The fixture supplies session/actor fields, a native-shaped level-up hierarchy and
the existing `CanvasConversion` service contract. That port creates real Unity
canvases in the target's original scene; it does not simulate the new owner
selection, transform matching or release logic. Fixed-fit frame service is an
explicit input, not execution of the full fixed-fit solver. Consequently this
suite does not claim native scenario bootstrap, complete converter integration,
shared transport, headset imagery, hardware performance, or fitting-limit proof.
The separate level-up/dialog/announcement suites cover bounded lifecycle,
callback authority and native continuation controls; the integration gate covers
unchanged conversion and shared size contracts.

Build738 also runs both generic-confirmation consumers: the persistent member
seated on level-up and the original standalone `DialogSurface`. Their actual
conversion options feed the production capture admission kernel. Production
camera, projection, scoped GrabPass neutralization, mip resolve and final display
kernels render 24 consecutive head photographs per route (12 poses, two eye
inputs). Every photograph is compared with an independent reference at the same
pose, with the authored full-frame backdrop disabled. The entire sequence is
retained even for a failing historical control. Fixed target allocation, private
layer leases and the outer capture scheduling loop are explicit resource ports.
The fixture does not execute the complete capture coordinator.

The new confirmation question and button geometry are fixture inputs. The real
TMP renderer and original game `ExtendedButton` pointer permission execute;
native confirmation session callbacks are counted ports. The GL GrabPass shader
is a mechanism witness using the original material's independently inspected
`One/Zero`, `LEqual`, depth-write and culling states. It samples the actual frame
without an artificial animation pulse; it is not the original Windows shader
program or a headset/D3D11 picture. Reverting either consumer's capture option,
or omitting scoped blur neutralization, must produce a measurable final-pixel
failure. These checks complement the separate native-material and complete
window-coordinator suites.

The conversion boundary now preserves the real `ConvertedPanel.IsAlive`
contract: the original target survives a successful release. Fifty closed ticks
must cause only one release; pooled reopen, native Yes/No permission, modal
raycaster exemption, desktop rescue, return to VR and DDOL scene unload remain
covered. A separate removal control restores the mistaken target-liveness lease
check. The repeated post-close release defect is distinct from visible-frame
instability; neither the lifecycle result nor the GL witness certifies headset
appearance or hardware performance.

Because game services are not bootstrapped, the retained Unity log can include
the native `ExtendedButton.OnDestroy` accessing unavailable game services
during fixture teardown. These messages are not accepted defect controls:
each control must still reach its named assertion after compilation succeeds.

Checks cover visible native glyphs before comparison, exact button pixel parity,
serialized callback removal, inactive construction, unchanged tracker permission
when the native reward click gate rejects, bounded localization, complete text
ink between original columns, later text births on the same pooled preview,
first confirmation ownership, native close/reopen, generic admission suppression,
accepted owner movement/resize, actual DDOL scene unload, and original standalone
admission after ownership ends. Each deliberately broken case must compile and
fail at its named assertion; an unrelated exception never counts as rejection.

Each run retains source copies/pins, native input pins, generated project,
executed fixture/editor assemblies, Harmony runtime, logs, images and per-case
results. After the exact editor launcher and escaped project editor/compiler
processes are reaped, `cleanup_completed_run` removes only regenerable caches.
Development failures remain evidence and are not promoted to successful runs.

Only presentation components are installed; native controllers, localization

The existing declared GL GrabPass witness remains the native blur fragment port.

Both real local consumer flags feed the exact production background-hiding body,
constants and release restoration loop. The exact converter target normalization
fragment preserves the measured frame when native stretched anchors collapse.
The exact distance ladder, nearest-rect distance, hysteresis, follower application
and shown-pose stamp execute; unrelated furniture/diagnostic steps are no-op ports.
The owned case uses the actual hardware scale (.08275 world units per authored

The independent reference draws the small dialog after its owner. The unowned
case excludes owner content rather than inventing an owner-overlap requirement.

With no capture resources or capture calls at all, each route renders forty
consecutive final head photographs: ten poses, two eye inputs, front and rear.
Compare every RGB pixel and separately count changes outside the projected native
small box. A separate native-only photograph must retain visible glyphs, so owner
text cannot make a blank dialog pass. Original large graphics restore on close;
all prior close/reopen/DDOL/permission/capture cases and controls remain. New
omission controls retain either full-frame backdrop or the member's owner tier.

The converter's host allocation/adoption and outer capture scheduler remain
explicit ports. Zero capture resources represents the logged refusal route; it
does not execute the general target allocator or an actual capacity refusal.
The owner overlap is a real ordinary Unity canvas, not the complete spatial
character-window head compositor. These native geometry and GL pixels do not
certify original D3D11 fragment programs, the real HMD image or frame pacing.
