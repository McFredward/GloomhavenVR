# Native flat-menu card depth proof

Run `python3 scripts/menu-depth-cards/run.py` from the checkout. The optional
repeatable `--case` selects focused cases. This local GPU suite needs the project's
Unity 2021.3.5, Xvfb, .NET and developer UnityPy environments. It neither produces
nor needs an installation archive.

The suite executes the production discovery pump, typed card registry, complete
root leases, direct early priming, eye capture/display code, original Unity UI
layout/masks and real TMP glyphs. Actual GH.Runtime components supply the seven
native card identities: full/mini abilities, items, round/base monster cards,
perk modifiers and scenario modifiers. Full action-only variants use the actual
FullAbilityCardAction/button target fields; no card/image-name classifier is used.

Gameplay/bootstrap/asset-load lifecycle bodies of these native controllers are
suppressed. Controlled original-widget image/text/layout trees, panel membership
and physical eye observations are explicit inputs. TMP essentials provide the
font atlas; screenshots do not claim to be original game artwork or headset
pictures. Native pool activation/reparenting is the input; the real lifecycle
observer/discovery code executes, while the campaign ObjectPool is not started.

The independent oracle lifts native flat screenshot ink onto a plane 10.4% of item
or full ability-card width, or 5.6% of every smaller card's width, then projects
through the actual head camera. Full/item cases also reject the prior 3.5% plane
and requires at least 60% more observed displacement on the same native artwork.
Build737 increases every accepted physical relief by 60% (from 6.5%/3.5%);
this does not change the original geometry or pixel-error tolerances.
Continuous white glyph coverage avoids unstable thresholded TMP stem centroids;
the geometric tolerance stays 1.8 pixels. Actual first automatic frames include
both pre-enrolled cards and popups born after the final menu tick, without manually
invoking early priming. The direct head is enabled; earlier failed manual-disabled
head hypotheses are retained in development evidence and are not passing proof.

Other proofs cover complete nested/generated text, both stereo selections,
readonly disabled controllers, late backing references/destruction/replacement,
XY-only native fitting, hide/reuse, physical
canvas exclusion, nested card coalescing, ScrollRect/RectMask2D, sliced transparent
art, tint/material identity, unchanged native controls/layout, missing-head/orphan
cleanup and exact native recovery pixels after a capture exception. The normal
native desktop path uses orthographic size 5/planeDistance 7. The additional native
size 450/planeDistance 7 clip stress belongs to the shared UI depth-normalization
integration and is not silently represented by the normal-path pass.

Causal source mutations independently remove early priming, root lift, complete
root membership, restoration, native item identity, nested coalescing, printed
visibility, late backing renewal and XY-only native fitting. A compile failure is never a mutation pass.

Each run first executes `scripts/menu-depth-cards/audit-native.py` against all 13
original scenes and the original GUI bundle. `native-authoring.json` retains exact
owner/component/field/Sprite/material identities and source hashes; no artwork or
mesh is exported. The old AttackModifierCardGUI widget only has a hide consumer;
the separate obsolete AttackModifier class has no active type consumer. Actual
perk/scenario modifier cards and monster hover/transition cards are covered.

Build729's `native-hover` case follows the original character ability overview's
actual `AbilityCardUI.fullAbilityCard` path. The audit pins both pointer/gamepad
prefabs, their 294x450/360x555 Full rectangles, the original button's persistent
OnPointerEnter/OnPointerExit callbacks and all six authored overview instances.
The real native `ToggleFullCardPreview` executes activation, original Full/Mini
layout, its transient Canvas and raycast blocking. Gameplay/asset services and
the existing TooltipOnWindow placement are explicit ports. The complete Full
widget is detached to the enrolled root, beneath XY-only native fitting, with its
native controller disabled; three pool reuse cycles per prefab must show correct
depth on their first automatic frames, without another Driver tick or root census.
Separate controls remove exact Full identity and card depth; both must fail the
new GPU proof. An additional item control restores only the prior relief amount.

This case passes against the unchanged Full registry from Build728. It does not
establish a missing native card type as the cause of the hardware report. The
fresh Build728 logs independently record whole-window character-pool fallbacks
on the same New Party display root. Integrated moving-character coverage belongs
to that resource repair; this isolated card fixture does not run a native model.

Evidence includes executed assemblies, pinned sources/native inputs, GPU images,
geometry/callback traces and failed attempts. Exact owned Editor/compiler cleanup
runs before `cleanup_completed_run`; regenerable caches are removed on success,
failure and interruption. Automated GPU checks do not establish headset quality.

The `native-ui-freeze` case executes 400 original Unity Images across two actual
ScreenSpaceCamera roots with independent active CanvasScalers, plus the audited
Overlay/Notification child shape. Over 24 real frames, both eyes use actual
expanded Camera.Render calls and restore camera matrices, native layout/TRS and
scaler state. Warm Driver root/ancestor/behaviour counters remain exactly still.
A real parent change and a new Image component born directly in onPreRender must
still be discovered; separate source controls suppress each edge. The original
400×48 comparison with/without a proposed observer guard was equally quiet, so no
unnecessary guard or fake hierarchy notification is retained. Read-only reflection
observes the actual private known-Graphic set without adding a product test API.

Build736's `head-text-736` exercises the actual `MenuDepthDisplay.RenderHead`
coordinator, private UI rasters and final head pixels. Real TMP title and Button
label geometry must survive all 64 front/rear, subpixel and pitched-eye/style
samples. Its colour reference uses the identical complete card-root loan and
native layout/materials with only backdrop depth helpers disabled. No bright
title or button glyph pixel may disappear. A read-only postfix observes the real
uGUI `DoMeshGeneration` worker mesh after its modifier chain and SetMesh; a normal
Canvas flush must restore the original local backing plane after each capture.
Three controls remove the backing separation, reverse its rear-view direction,
or omit mesh restoration. The prior cases and seventeen controls remain intact.

`--graphics-api glcore|vulkan` selects an actual editor backend and the report
records `SystemInfo.usesReversedZBuffer`. The original D3D11-only native-card
programs cannot execute in this Linux fixture; two explicitly declared shared
shader stand-ins from the desktop suite exercise dispatch and depth state.
They are input-pinned and do not certify native D3D11 effects or headset pixels.
# Build738 immediate level-up hover

The level-up highlighter uses `UILevelUpCardHolder.PlaceNewCard(immediately:true)`
and its native pool; it does not use the loadout row's `ChangeFullCardPosition`
route. The new case executes original `HighlightCard`, `PlaceNewCard`, `Hide`,
`SpawnCard` and `RecycleCard`, repeatedly swapping two actual pool identities
before the first automatic head draw. First-eye rasters must exactly match an
independently aligned window-plane reference, without waiting for the generic
flatten walk. Both eyes, two window yaws, manual/flat/VR-off/retired/foreign scopes,
native shown callbacks and the unchanged non-immediate reveal are covered.

Campaign Init/Show/art decoration and pool-return gameplay cleanup are explicit
fixture ports. A private GH.Runtime copy replaces exactly four calls to the game's
custom `LayoutRebuilder.Enable(bool)` with bool-consuming `Pop` instructions because
Editor uGUI lacks that API. All native method instruction streams are compared;
only the four setters in `SpawnCard`/`RecycleCard` may differ. Editor layout remains
enabled, so this does not establish original game-uGUI gate timing. Native pose,
parenting, pool selection, activation, callback and head/UI render operations run.
The original game files remain read-only. Actual native game art/D3D11 and headset
appearance still require hardware acceptance.
