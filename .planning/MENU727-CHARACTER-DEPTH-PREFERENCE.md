# Build727: optional live character depth

## User direction and delivery

The maintainer asks for live character preview depth to be switchable, enabled by
default on every system. During this turn the maintainer explicitly clarifies
that the Windows installation script already builds the ZIP. This supersedes
earlier local archive requests: integrate/push dev source without building or
delivering a new local archive. AGENTS.md records the updated workflow.

## Implementation

`[WorldUI] CharacterPreviewDepth` is a persisted local boolean with the single
annotated `Defaults.CharacterPreviewDepth = true` default. Its bind has no platform
branch, and no PC/Steam Frame profile overrides it. BepInEx retains saved choices;
the default does not forcibly overwrite an intentional disabled value.

The normal door is VR Options > Panels > 2D screen > 3D character previews. The
advanced screen/depth topic also exposes it. Caption, description, player help and
the playing guides are English/German. This is the user's explicit local viewing
choice; it does not change shared absolute window geometry or native authority.

Character discovery checks the preference at its existing Tick and first-capture
flush boundary. Disabled capture calls the existing character-only Shutdown,
restoring borrowed textures, unregistering its exact sources and releasing owned
eye targets. General story/decorative depth remains registered. Re-enabling starts
one cold discovery of existing native previews; no scene sweep runs while off and
no window reopen/native Display/gameplay call is needed. The original flat live
image remains available, including its original animation and native hide gates.
Common character geometry/rear rendering from726 and accepted story/movie assets
are unchanged.
