# UI-only mixed-reality backings — build 532

## Evidence and scope

The local `LogOutput.log:17` identifies build 531, assembly 1.0.5.0. Remote
`LogOutput.log:18` remains historical build 500 and is not evidence for this fix.
Inspected `wasser_hintergrund.jpg`: an opaque dark slab is visible inside the
scenario near the reported custom-water surface. The screenshot cannot identify
its Unity renderer or distinguish an underlay, fill and rim by instance ID.
Local log line 981 explicitly records `GloomhavenVR.MrUnseenRim` entering the
scene. It proves the scenery-backing system is still active, but does not prove
that particular instance produced the photographed pixels.

The current user ruling is general: no MR backgrounds inside the play area;
backings belong only to UI. This supersedes the older unseen-tile exceptions.
Build 530 restricted supplemental spatial adoption, but deliberately retained
unseen-family/transparent-Preview adoption and native cliff backing. Therefore
its narrower fix could not enforce the newly clarified UI-only boundary.

## Change

- Replace the live MR tick's scenery-construction call with retirement of every
  owned scenery underlay, fill and rim. No native renderer, material, transform,
  water shader or fog animation is changed.
- Teardown disables these owned renderers immediately before deferred Unity
  destruction, frees shared rim meshes/materials and clears tracking. Partial
  construction resources are included; an empty state is a cheap no-op.
- Preserve camera chroma-key, sky removal, UI `BackingsWanted` and the complete
  independent `WorldUI.MrBacking` implementation.
- Keep all seven persisted scenery configuration keys but mark them INERT in
  English/German descriptions and default annotations.
  Historical construction/diagnostic code is intentionally dormant to preserve
  protected grep tokens and provenance; it has no live entry-point caller.
  The focused bindings pin that fact so a later reconnect is not accidental.

## Additional creation-route audit

`WaterTerrainVR` has no MR backing registration or geometry path. The remaining
`WorldUI.MrBacking` registrations are converted UI panels, explicit TMP captions,
UI tooltip/widget surfaces and pre-existing UI plate materials; they do not scan
or adopt scene MeshRenderers. `ActorBars`, `PropInfoSurface` and `StatPanelSurface`
already suppress panel backings for their in-scene presentations. The legacy rim
builder has only the now-dormant scenery implementation as caller. These UI
routes remain unchanged, including multiplayer mirrors.
