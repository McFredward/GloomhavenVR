### Every checker was made to fail before it was believed

This is the part worth carrying forward. Each of the four was green on the whole tree at some
point *while being incapable of failing*, and only a deliberate control found it.

**`check-surface.py` — my control was wrong twice before the checker was.** Rewording
`"Remote pick banner: "` changed nothing, because the token rule is deliberately two-or-more
SHOUTED words; including sentence-case strings would make every string edit a failure. Renaming
`"VOICE SPATIAL up"` changed nothing either, because `VOICE SPATIAL` still existed at three other
sites and was therefore still greppable. The checker was right both times. Only renaming a
**unique** marker — `ACTION DID NOT COMMIT` in `UiSoundEar` — failed the gate.

It also could not see anything at all from a foreign working directory: `SRC` was the relative
string `"src"`, so `os.walk` found nothing and an empty census diffs clean against an empty
census. Resolved from `__file__` now.

**`check-partial-order.py` — four defects, all found by a synthetic two-part type.**

1. `(?P<mods>(?:static|readonly|…)\s+)+` repeats the *named* group, and Python keeps only the last
   repetition. `internal static readonly int Seed` yielded `mods='readonly '`, so **every
   `static readonly` field in the mod was invisible**. It passed the entire tree while being
   structurally unable to fail.
2. `=(?!=)` matched every expression-bodied member. Seven fired; all seven were false, because
   `static bool Foo => _bar;` is evaluated on each *read*.
3. A cross-part **method call** is not a dependency — methods have no initialisation order. The
   first genuine hit was `VROptionsTab::DependencyParents <- ::Id`, and `Id` is
   `section + "/" + key`. The traversal follows methods and reports only fields.
4. A one-line type body was invisible to the line-based walker — the type did not even register
   as having a part. Found because a one-line probe reported clean and *the probe was the bug*.
   Now refused outright.

**`check-instrument-writes.py` — 197 → 84 → 66, and the two narrowings are the tool.** Fixing
what counts as a *read* (assignment targets anywhere in a `=` chain are writes, not reads) took
197 → 84. Fixing what counts as a *diagnostic* took 84 → 66: the name pattern is only a seed, and
a method is promoted when all of its callers are already instruments, to a fixpoint. 294 seeded +
112 promoted = 406 of 4 358 methods.

**`check-frame-order.sh` — verified by swapping two calls** the new marker orders; exit 1, both
lists printed side by side.

### And one false positive that would have poisoned every remaining guard run

The first `check` after committing 1.1/1.3 reported `CHANGED BuildInfo.cs` with `git diff -- src/`
empty. The commit mask is `\b[0-9a-f]{9,40}\b` — nine or more — and `BuildInfo.Commit` carries
git's **seven-character** short hash. The guard was going to show one red line after every commit
of this refactor: the same defect class as the `-dirty` suffix and the `[branch]` token that
`LOG.md` already recorded, and the same reason it matters.

Lowering the generic threshold to 7 would start masking ordinary hex words, so the two revisions
that can actually appear — the baseline's recorded rev and current `HEAD` — are masked **by
value**, longest prefix first. Verified across a real commit boundary.
