## Scope of the new game change

The read-only helper observes public host OpenVR foreground/background fade,
grid, dashboard, focus/render-owner and narrowly named setting values. It uses
an isolated Background client and exact reviewed public interface versions;
it never calls setters, changes focus, creates layers, starts/stops SteamVR,
edits the sender, alters rendering/resolution or installs anything on the Frame.
Hardware property text is used only for bounded identity classification and
is not serialized. API calls in a snapshot are explicitly non-atomic.

Observation runs only at Debug during a genuine requested native Frame/Steam
Link MR session, including when the independent edge-quality lease is disabled.
Ordinary users and standalone launch no helper and stage no observation files.
All resource verification, child launch, pipes and teardown run away from Unity's
thread. One owner prevents overlapping pending/stale acquisitions. Off, session
end or Debug-off closes only that child's stdin. Unconfirmed teardown suppresses
further acquisition. Cleanup grace may retire this child, never MR or Steam.

Output is finite, closed-schema JSONL: at most32 deduplicated snapshots,1024bytes
per line and32768bytes overall. Missing/error/nonfinite readings are explicitly
unavailable. The report budget stops observation API calls; it does not expire
passthrough or automatically restart anything. The child remains idle until
ordinary owned EOF. There is no new test-pattern setting or player action.

This is a diagnosis build, not a claim that menu composition, first-frame edge
transition or full-resolution MR transport has been repaired. A future fix must
show which public state actually changes before writing compositor state.

## Rebuilding the embedded helper

Canonical sources belong to the independent native companion project. Use
`scripts/build-steamlink-compositor-monitor.sh <native-checkout> <sdk-directory>`
with its exact reviewed public `openvr_capi.h`. The script refuses uncommitted
source inputs, runs the companion's portable fixture, compiles our own Win64
child, and records source/header/compiler/output hashes beside the embedded EXE.
No Valve header or new Valve binary is copied into the game repository. Ordinary
Windows installation uses that committed resource and requires no new tooling.
