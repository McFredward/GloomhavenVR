# Multiplayer animation handovers — ModBuild 501

The September 14 multiplayer test used version 1.0.0 / ModBuild 500, commit `7745d90c8`,
on both clients. Main `LogOutput.log:17,70` and remote `LogOutput.log:18,71` identify
the same runtime. Main ran VirtualDesktopXR; the peer ran SteamVR/OpenXR in Meta
compatibility mode. Images in the debug directory predate this test.

## Report and evidence

The maintainer observed a remote card flight beginning toward a pile while the source card
remained briefly on the board, and a remotely held figure walking through the air from its
held position when the game started its movement. Both concern the boundary between a
temporary VR presentation and the original game presentation.

The card logs report immediate flight launch while the mirrored recess still reports its
card. Source review also finds a normal dock-vanish animation on clearing a remote card:
that animation must not keep a stationary copy after the flying copy takes ownership.

For figures, native `ActorBehaviour.SetLocoTarget` captures its start position and path
distance from the current transform. Merely restoring native Update after receiving a
release packet is too late if the path already started at the in-hand pose.

## Required behavior

- One visible card owns each transfer: the original source before departure, the flight
  during transit, the destination on arrival. Delayed board state must not resurrect the
  old source or make the destination appear early. This applies to both boards and all
  supported flight routes, including rest, burn, active cards, hand returns and recovery.
- Burn playback must finish before departure. Existing native card fronts, back secrecy,
  material overlays and animation content retain their current rules.
- A held figure returns immediately to the board before a non-idle native action derives
  its start from the transform. Remote held samples cannot reclaim it during that action.
  The latest hardware ruling supersedes the older forced-release glide requirement;
  ordinary manual idle releases retain their existing glide.
- Release only presentation ownership: never alter authoritative position, path, game
  actions, decisions or native network state to repair a visual symptom.

The final review also closes native hand-return geometry and landing gaps: recovery captures
the layout home pose/rotation/scale before hover or reflow, uses the hand parent scale and
hands over the exact card at its current home. Active landing retires only that card's
arrival grace; actor/card generations reject obsolete delayed incoming flights before they
can draw or undo a newer departure.

Version remains 1.0.0. This hotfix targets dev; the existing main release/tag is unchanged.
All VR peers must use the same new ModBuild. Hardware confirmation remains necessary after
the source regression checks, particularly simultaneous flights and action starts under
network latency.
