# Native party container handover — ModBuild 502

Version remains 1.0.0. This hotfix follows the build 501 multiplayer fixes on dev.
It changes the DLL only; the main release/tag and original asset bundle remain unchanged.

## Proven cause

Fresh build 501 logs reproduce the missing private battle-goal window for quests 078 and
039. Native code enters loadout interaction, clears its hide request and opens both the
inner party window and the battle-goal picker. The VR story curtain still refuses their
outer window, so the player sees only quest information and cannot complete required choices.

The actual native topology is `New Party display` (`UIWindowID.PartyPanel`) containing
`Party Display UI ` (the different UIWindow owned by NewPartyDisplayUI). Build 500 checked
only equality with the inner owner or descendants of that owner. Its test fixture also used
a single owner window and therefore missed the real ancestor relationship.

Multiplayer success had another cause: the older mutual-hold fallback lifted the curtain
after 90 ticks. In both new single-player attempts, the quest popup appeared after 19/18 ticks
and cancelled that fallback while the required choices were still hidden. Waiting longer or
loosening a generic empty-room check would not repair the identity mistake.

See [MAP-502-EVIDENCE.md](MAP-502-EVIDENCE.md) for exact log lines, distinct build banners,
the two attempt timelines and the independent implementation review.

## Change and boundaries

`LoadoutWindowOwnership` now admits the nearest native PartyPanel ancestor containing the
current inner owner, in addition to the existing owner/descendant case. It matches that actual
instance; another PartyPanel elsewhere, a common canvas, a higher wrapper or unrelated siblings
receive no exemption. The lookup reads the current hierarchy without a retained cache.

The live map/loadout/open-window conditions and the loadout manager's hide request remain
required. Native intro and multiplayer waiting states therefore retain their existing refusal.
No native Show/Hide, choice, game state, networking callback or transition is invoked to escape.
The existing float conversion brings back the original enclosing window and its original widgets.

The handover diagnostic names the admitted window, its ID and the native inner owner, including
whether those are the same instance. Its existing `STORY CURTAIN LOADOUT HANDOVER:` marker is
preserved. The normal ancestor refusal walk and the native party-hide patch were also reviewed;
they require no additional runtime change once the correct outer member is admitted.
