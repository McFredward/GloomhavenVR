# MP761: native scene opacity and actor-symbol MR ownership

Scope: paired Build 759 hardware report, items 4, 8, 9; Class C final integration. This lane changes the PC mod only. It does not modify the SteamLink sender/Frame patch or install anything on a headset.

## Source causes and changes

1. `MrBacking` previously relied on a post-conversion opt-out for some actor UI. Admission and retirement now also recognize the actual native ancestor owners (`WorldspacePanelUIController`, `WorldspaceUI.AttackModBar`, `AttackModElementUI`), including inactive parents. In-world health/modifier/draw symbols never acquire a readability plate. A genuine window containing card/modifier artwork remains a window. The supplied logs do not prove a flag race; semantic ownership is the source-proven defect.
2. The installed native `GUI/AbilityCard_Shd` and several particle shaders use the RGB straight-alpha factors for destination alpha too. A half-transparent draw over an already opaque virtual card, UI or wall changes its alpha from 1 to 0.75. That creates room-camera leakage even though the original RGB looks correct. The existing opaque-depth stamp cannot protect depthless opaque UI drawn later in the transparent queue.
3. The bank now includes seven separately named derivatives of the original serialized native shaders. Every original compressed D3D11 program, keyword/program index, property, RGB factor, depth/stencil/cull/write-mask descriptor and independent-MRT flag remains byte-identical. Only shader identity and an alpha-source-factor binding differ. Native alpha coverage uses `Aout = As + Ad*(1-As)`; additive light retains destination coverage. No generic shader, scenery backing, threshold/key colour or additional camera/render pass replaces the native material.
4. uGUI batches `CanvasRenderer` materials before camera callbacks. An attempted camera-local binding swap was one camera late in actual GPU output; it was rejected. While the MR source is armed, only admitted exact-native UI shader clones remain privately bound. Their alpha-only fixed-function source factor reads a uniquely named global at draw time: native 5/1 outside the head, coverage 1/0 for the owned head. Original public `Graphic.material`, stencil producer, geometry, RGB and callbacks stay intact. Mesh-renderer variants retain the existing head-local borrowing path.
5. Passive GraphicRegistry, base Graphic.UpdateMaterial and exact ObjectPool.Spawn return observers enroll first arrivals/rebuilt stencil materials immediately. Each postfix catches its own failures and bounds diagnostic reports without changing original return values or exceptions. Unrelated pooled renderers are filtered once before entering every-eye work; later shader changes remain discoverable on the cold refresh.

The two globals are not material properties. Each nested camera saves/restores the prior scoped values. Disarm restores the pre-arm values and only still-owned material bindings; external CanvasRenderer/renderer writes win. OFF marks only restored native graphics material-dirty so the next ordinary native batch uses the original binding. No per-frame ForceUpdateCanvases, full-scene scan or shader recompilation occurs.

Already-correct AbilityCard_Low and unknown/property-bound or unsupported families remain original. Existing owned shader variants remain unchanged. This is bounded audited-family coverage, not a certificate for every game shader or every graphics API.

The shipped bank is249,360 bytes, SHA256 `6a51e25b930377e8599306ad5c6c812b293840009fe90fe31a71a0162eabb781`: sixteen pre-existing owned shader objects retained byte-identically, plus seven native-program derivatives. Their original programs target D3D11. Linux OpenGL/Vulkan native-program support is not added by this bank; the mod's existing unknown/unsupported fallback remains unchanged.

## Preserved failed experiments and limits

The initial native inventory attempt detected a stripped inner Unity version (the actual UnityFS header remains2021.3.5f1). A second attempt caught a UnityPy container reread bug that retained only the last new path; it was corrected by accumulating/saving the container once. Neither faulty bank was shipped. Full non-alpha/program audits and all 23 paths now pass.

Per-camera CanvasRenderer reference swaps failed in GPU output, despite apparently correct material snapshots, under both pre-cull and pre-render. Their receipts/event trace remain preserved. The first final-matrix attempt also caught a fixture opaque-wall backface; an independent wall-only pixel precondition was added before evaluating overlay composition. A subsequent fresh-graphic test correctly exposed that CanvasRenderer.Clear clears geometry as well as materials; its explicit native rebuild port now dirties/rebuilds both. These failures were not converted into passes or hidden.

The source-loaded native shaders and their compiled D3D11 programs are audited and load as objects. This Linux machine does **not** execute those original D3D11 programs. The RGB/alpha/clip/state witnesses use explicit test-only source-output ports with the exact audited fixed-function states, actual native uGUI/Harmony/camera callbacks and real GPU output; additive native two-pass program identity is audited rather than emulated as a full native effect. The fixture's pool implementation is an explicit return/exception port with the exact native signature, not the publisher's complete gameplay pool. There is no live XR session, SteamLink receiver, D3D11 or headset picture proof here. A fresh headset test must verify that the supplied native shader coverage matches the reported card/effect surfaces; no StandaloneFrame improvement is claimed by this SteamLink-only change.
