## Source-proven first-picture cause and repair

Continuous native hover capture can change the required/prepared census while
the immutable card/list bundle is still fragmented. The previous queue canceled
that useful assembly just because its bundled census differed. A hover partition
leaving membership also canceled all useful neighboring originals. Separately,
visibility regain could request a new full original before the previously queued
exact baseline had finished. Repeated census churn discarded received progress.

The current repair lets the useful immutable assembly finish. The existing
immediate manifest lane carries current membership; the actual receiver rejects
an older census and cannot render a retired member. A genuinely newer required
original still replaces superseded original content. Named future cumulative
dependencies, changed-template replacement, session replacement, actual close,
ordinary repair and existing event/bandwidth budgets remain intact.

Visibility regain reuses a full baseline still in delivery. Once delivered,
actual compatible-peer original receipts still govern reopening repair. An
independent existing `NeedsOriginal` request is retained rather than erased by
this visibility bookkeeping.

## Why the previous green admission proof missed it

The 639/646 packed-atlas case destroys live owner Sprite wrappers after its first
capture. During its arrival timer it consequently calls only `CaptureMotion`,
freezing owner artwork/census updates. Its later continuous-render case starts
after admission. Thus it proved a static original transfer and separate later
motion, not actual continuous capture while first originals were fragmented.

The new `--live-hover-census` challenge retains real owner wrappers while keeping
the observer's independently prepared native asset bank. It calls actual owner
`CaptureCore(fast:true)` throughout arrival, including native hover visibility
changes. `--withdraw-hover` additionally unregisters/re-registers that original
source before delivery. The previous independent cold-atlas/alias proof remains
inherited evidence; this new challenge does not pretend it repeated that separate
cold-asset test.

The fixture uses the actual 50 ms scheduler, native codecs, fragmentation, actual
avatar receive/coalescing methods, native binding validation/mount, Canvas rebuild
and Camera.Render/ReadPixels. Its existing complete-picture wall-clock deadline
is still one second, including applied/rendered originals, with the same saturated
other presentation queues and byte/event limits.

## Overlay flicker: separate, still under investigation

The supplied logs do not record the actual individual overlay's source/observer
active, cull, CanvasRenderer alpha or inherited alpha when it blinks. Admission
and aggregate painted-module counts cannot distinguish an intentionally changing
native hover fill from disappearance of its permanent frame.

The native enhancement widget intentionally changes its fill alpha on hover and
selection. Forcing all graphics/CanvasGroups visible would change native behavior
and is not a valid repair. No alpha override or speculative fallback has been added.

Bounded Debug-only source/observer transition traces now identify exact session,
module/address, header sample/visibility/parent alpha, actual membership/root
activity, visible ink, graphic enable/cull/local and inherited transparency,
canvas state and CanvasGroups. Observer samples occur after the numeric/effect
pass; diagnostics cover dynamic holder/highlight partition addresses. Scans and
formatting are gated at Debug and capped per module and 30-second window; normal
user logging is unchanged and teardown clears retained diagnostic state.

The previous native admission fixture's furniture-order boundary is a no-op and
its census-continuity case pins aura alpha/turns off a native area variant. These
proofs establish the named census/latency repairs, not per-graphic overlay parity.
Final furniture sorting and actual native hover/selection output require a separate
causal rendered comparison before claiming the reported flicker is repaired.
