# Build 546: map controls and area-effect targeting

This is the 1.0.7 hotfix line based on the released 1.0.6 runtime, without immersive
town services. Builds 538–545 and transport IDs 78–81 / messages 19–22 remain reserved
for `feature/immersive-town-services`.

## Findings and changes

- The 3D button rail enumerated `UIGuildmasterButton`; the campaign city-event button
  is a separate `UICityEncounterButton`. Native `UIGuildmasterHUD.Init` explicitly
  enables that control only for campaign mode. Guildmaster has no city-event button.
  Its `GUIAnimator`, image state and native interaction restrictions must follow the
  original control. The event opens `UIEventPanel`, already shared as `Encounter`.
  Existing `EncounterChoice` forwards client choices to the modded host, validates
  event/screen/option identity, and uses the native replicated continuation for everyone.
- `ReleaseMapRoomFloats` called native `Hide()` even for a presentation-only map
  switch. Returning to 3D emits no new native `Show` edge. Preserve native state on
  that exit and re-enroll the original character/quest windows on 3D entry until
  conversion succeeds. Native tutorial unlock and story/journey restrictions remain.
- AoE rotation already used horizontal movement of the stick opposite the turning
  hand (default left). The extra derived `BoardTargeting` requirement excluded
  native object-placement and damage targeting that can remain in choreography
  `Play`. Native display state, acting-player authority and modal restrictions decide
  eligibility. A clicked stick remains available to world grabbing. Exact native
  Tinkerer message keys now name the actual controller side in English and German.
- Map-button hints retain native presentation, placed flat beside the hovered cap.
  A dedicated bounded presentation stream (message 23 / fragments 24 / TLV 82)
  carries complete pictures and explicit disappearance, through the existing
  compression and 864-byte / 50 ms aggregate event scheduler. It does not send game
  actions. Old protocol layouts and the version byte are unchanged.

## Evidence limits

The current main `LogOutput.log` identifies NPC build 544; the remote log identifies
historical build 500. These are not runtime confirmation of this hotfix. Causes above
are established from production/native source; headset presentation remains unverified.

## Hardware checks

1. Campaign: city-event cap visible, correct enabled/disabled state and native pulse;
   open the encounter, let both host and client choose options and finish it.
   Guildmaster: no city-event cap.
2. Switch 2D/3D repeatedly (including more than four cycles), both map modes and an
   initial 2D load. Character and quest windows remain usable. Story/loadout must
   retain their intentional window visibility and continue normally.
3. Hover ordinary and disabled map caps: native hints lie flat beside the cap,
   disappear correctly, and are identical for peers, including overlapping hovers.
   Check a late join, scene departure and 2D/3D switches while a hint is visible.
4. Tinkerer rotation tutorial: readable controller name; default left stick left/right
   rotates ranged AoE in 60-degree steps; right stick still turns the player.
   Check swapped turn hand, turning disabled, object-placement effects, melee facing,
   non-acting spectators and stick-click world grabbing. Confirm the selected rotated
   effect normally on the control board.
