# NPC639 first-picture proof audit

This proof answers the paired Build638 failure without treating admission as a
visible picture. Hardware remains the final authority for headset appearance.
The local test enforces one actual second from owner capture to a complete
rendered observer frame. It does not claim an arbitrary real network or HMD
latency guarantee.

## Previous blind spots

The638 fixture's simulated send clock passed while actual Unity took1.295s.
Its source rows used an editor mobile TMP material instead of the game's full
`TextMeshPro/Distance Field` shader:14 complete native rows then occupied8.2KiB,
versus roughly12KiB with the real property's density. Splitting arbitrary text
partitions did not reproduce actual mount and hierarchy dependencies. Loaded
sprites on both sides hid dormant native `SpriteAtlas` members. Active roots and
successful admission flags did not verify that every visible option, offered
card, ring and confirmation had resolved artwork and content.

The actual638 logs first assembled all33 required originals around4s, then never
admitted the mage picture because its exact Poison variant remained unavailable.
The read-only game atlas contains two Poison originals with different pivots;
name-only discovery would not be a valid repair.

## Executable proof boundary

`scripts/npc-first-picture639-runtime/run.py` binds current production capture,
`ExtrasSendScheduler`, fragmentation, the actual avatar receive queue/apply
methods, native binding validation/apply, offered-card mount and motion. It
retains hashes of every compiled source, the executable, complete runtime logs,
measured stages and an actual observer PNG under `.planning/debug/npc639/proof`.
No production runtime method is replaced or changed by this harness.

The native hierarchy reader restores original game layout, complete26-node
improvement rows, original sprites and the full native TMP shader/property set.
There are33 required and59 prepared native hierarchies, including14 complete
option rows, inventory parts, confirmation buttons, the physical print, native
ring and native pooled selectable areas. Observer font sizes, text and image
colors deliberately differ from sender output; complete owner originals must
replace them. All eight existing non-town queues remain saturated, with the
actual864-byte event limit and real50ms clock. Metadata, rather than images,
travels through the actual codec.

A byte-exact895-member original BattleOverlayCanvas bank exposes the same dormant
packed sprites as the hardware run. The owner-only wrappers are destroyed after
capture. Two independent real `TownServiceAssets` registries model the otherwise
global object state in one editor process. The loading preparation invokes the
same actual `Assets.Scan` used by production's native-template initialization;
its cost is reported separately. Owner native UI is actually rendered before
interaction, matching the TMP shader already used by ordinary local UI. The
source's read-only assets, pixels and packed geometry are never substituted.

The final timed frame calls actual binding validation for every expected active
asset, compares visible original text/font sizes/images, rebuilds all canvases,
and invokes actual `Camera.Render` plus readback. A visible root cannot satisfy
this proof while required inner content is absent. Editor software rendering,
the portable native hierarchy adapter, a constructed physical card-model print,
and absence of real Bolt/HMD transport remain explicit limits.

## Diagnostic evidence so far

The cold original workload reproduced a strict deadline failure. With33 required
originals and all59 prepared bases, first assembly was0.52445s but the complete
render was1.338335s: capture0.049s, decode0.0158s, actual receiver apply0.6845s,
canvas0.0146s and final render0.0130s. Original packed-atlas resolution, measured
separately by its owning worker, consumed0.579s for all895 originals. This proves
that the additional cost was actual cold asset resolution/build/apply, not the
simulated send clock or software shader compilation. Production now performs
this exact discovery during existing map loading.

Final candidate, omission controls, continuous pose/hover and merchant results
will be recorded here before integration. No complete-gate or headset pass is
claimed by this focused proof.
