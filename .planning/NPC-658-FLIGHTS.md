# Build 658 native card return repair

## Evidence and source causes

Both frozen hardware logs in the main checkout's `.planning/debug/npc658/inputs`
identify Build 656. The supplied `flug_karte_grau.mp4` shows the physical body
rising above its parked front around 4.7 s, then the front disappearing around
4.9 s. These relative video times are not a claimed wall-clock/log correlation.
The log records short native returns and separate numeric/artwork traffic; it
cannot establish which exact surfaces reached an observer's renderer together.

The source and runtime controls establish four defects:

* The old budget admitted independent body/front module returns. Three actual
  native cards with body registrations preceding their print registrations show
  a split physical picture. Restoring the exact Build 656 budget fails the
  between-receipt front/body coherence assertion. The smaller UI boundary case
  measures a 9.495508 mm split on render frame 7.
* Hidden prepared stock originals reused cached header visibility during fast
  capture. An artwork repair could also independently reopen/move a physical
  partition before its numeric return. Restoring either old seam fails the
  prepared-first-frame or actual native metadata-before-clock control.
* Repeating the complete 38-float receipt for every partition makes whole-card
  atomic admission exceed the unchanged 864-byte event. The imported Full print
  plus original action prototypes has 16 print parts and one production body.
  The former all-or-nothing 14-part attempt sent zero bytes. The final sender
  stages larger pictures against one immutable source instant and exposes every
  part together after the receiver has their exact original identities.
* Native ability and merchant steps cap elapsed advancement at 50 ms. Predicting
  wall-clock age unconditionally makes a later low-FPS receipt rewind the phase.
  Actual extracted 8/15-Hz steps reproduce this with the exact old clock.

## Production change

The sender retains the original 28 common floats once and every original child's
10-float geometry. Same lane/service/session/public claim/hand/revision and exact
common native receipt define a cosmetic group; this contains no gameplay card ID.
Actual live numeric source visibility and parent alpha accompany each part.
Cached artwork retains its last published physical header only while that SAME
module has an actual active native sampler. Its native nodes/content still update,
and native gameplay/controller continuation never waits for an observer or ACK.
This addresses the concrete prepared-stock path exercised here. A hypothetical
private offered-print withdrawal before any independent stock identity is
announced is not given an invented cross-lane identity or a blanket guarantee.

Large groups finish an immutable source snapshot before sampling the next moving
merchant destination. Membership, structure, liveness, native curve/revision and
source visibility changes invalidate it. One finite rotating ordinary turn selects the oldest actual per-slot last-send
clock across live/fan/cold categories while returns remain continuously dirty.
No event budget or source duration is increased.

The receiver waits for all declared parts and matching originals before one render
activation. It accepts either original/numeric receipt order. Older/equal-time
incomplete membership may wait; a strictly newer contradictory census proves
withdrawal. Loss, per-part reorder, native completion, every newer ordinary root
hand style, explicit hide, lifetime expiry, peer retirement and network reset have
bounded retirement controls. An older reordered root cannot cancel a current
return and a late old subset cannot resurrect an interrupted one.

The clock retains the source-to-observer mapping, derives authored advancement
from exact source-age/time history and never rewinds an already painted phase.
Merchant exponential returns measure progress from decreasing remaining duration.
Identical active clock samples remain dirty at the existing numeric cadence, so
an actual source pause can report zero advancement. Native easing, endpoints,
duration, geometry and public map artwork policy are unchanged.

An unexpected owner hitch cannot be known before its next receipt. In the actual
100-ms hitch control, the earlier prediction leads the capped source by about
50 ms and 55.3 mm at the most displaced ability sample. The renderer briefly
holds that phase; the actual owner catches it in five subsequent 90-Hz steps.
An authored pause similarly causes a bounded hold. Fixed 8/15-Hz clocks match the
actual extracted source trajectory after initial rate calibration. This is not a
claim of universally exact wall-clock pose through unobserved hitches.

## Additive wire record

Message 26 and protocol Version 3 are retained; old records 97/107 and Kind 8
bytes are unchanged. Record 113 is unknown-skippable within the existing byte-TLV
grammar. Each fragment contains `totalBody:u16, offset:u16, payload<=251 bytes`;
contiguous fragments reassemble inside one already bounded packet. Duplicate,
conflicting, interleaved and noncontiguous fragments are rejected atomically.

The logical Kind 10 body is:

1. Existing 17-byte kind/lane/service/session/public claim/leader module/structure.
2. Hand byte, revision u32, frozen source sample float, 28 native floats.
3. Member count byte (1..64), sorted `{module:u16, structure:u32}` members.
4. Part count byte, sorted `{index:byte, visible:bool, alpha:float, child:10 floats}`.

Body length is `140 + 6*N + 46*P`; every fragment adds six bytes including TLV
header. A full 13-member picture is 861 raw bytes including the 21-byte packet
clock. Larger 14/17/24/40/64-member cases make bounded progress without trimming
children. Validation preserves all original unit-quaternion, positive-scale,
curve/parameter/hand/revision/reserved-field checks and rejects future source
timestamps. The declared wire bound is 64 members; the actual imported print is
17. This proof does not assert support for an arbitrary larger physical original.
