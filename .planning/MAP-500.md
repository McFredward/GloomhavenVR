## Observed failure

The September 14 offline test used build 499, dev `ed35cfb25`. After the story, the game
opened battle-goal selection inside the existing party window. The story curtain still
refused that same root. The native quest-information popup returned as expected, but fooled
the generic mutual-hold fallback into accepting the transition. Required choices stayed
inaccessible while rendering and input continued: a UI softlock, not a stopped game thread.

A subsequent VR icon click bypassed the native map lock and restaged a travel location.
The adopted quest window then exposed the offline travel button despite the committed journey.
See [MAP-500-EVIDENCE.md](MAP-500-EVIDENCE.md) for the ordered log/source evidence and
[MAP-500-TRAVEL.md](MAP-500-TRAVEL.md) for the input-mask analysis.

The remote logs are historical build 491, and no new screenshot captures this incident.
The current logs identify the older story-curtain mechanism directly; they do not establish
the previous card-loss hotfix as its cause.

## Implementation

- `LoadoutWindowOwnership` recognizes the native party root and its descendants while the
  loadout is open, the party window is open, and the manager has released its own hide request.
  Native code retains that request during the introduction and multiplayer readiness barrier.
- `StoryComposite.CurtainRefuses` exempts only that current loadout content from the frozen
  member set. It does not force-open a window, choose goals or call a native gameplay handler.
  The withheld count uses the same verdict; the one-time `STORY CURTAIN LOADOUT HANDOVER`
  diagnostic identifies the actual release. Other story-hidden panels stay under the curtain.
- `MapInputGate` restores the native map mask's admission rule for laser/finger hover, clicks,
  deselection and remote selection adoption. Hover exits still clear old previews. Locked
  remote edges are consumed once and never replayed into a later phase; their log now says so.
- Offline travel presentation requires an unlocked native map. Online quest readiness keeps
  its independent native toggle visibility/state rule, so the map lock cannot hide a required
  ready action. Normal unlock restores the ordinary input and travel paths.

This is a native ownership handover, without a new timer or a broad escape from story masking.
It allows the original battle-goal, card and equipment widgets and their normal conversion.
An independent worker reviewed the conditions against both offline and online native flow.
